# 移动端阶段 0 基线

## 1. 交付范围

本文是成员 B 对阶段 0 的移动端交付记录，服务于 TB-0001、TB-0003 和 TB-0004。

阶段 0 只确认移动端 workspace 入口、页面和状态边界、后续 Expo 初始化要求以及设备验证输入。当前不实现移动端业务页面，不接入真实地图、天气、模型或用户数据。

## 2. Workspace 入口确认

| 项目 | 当前基线 |
|---|---|
| workspace | `apps/mobile` |
| 包名 | `@trailbook/mobile` |
| 技术路线 | React Native + Expo + TypeScript（后续初始化） |
| 当前状态 | TypeScript 占位入口，提供最小构建脚本 |
| 根目录验证 | `pnpm --filter @trailbook/mobile build` |
| Expo 启动 | 阶段 0 暂不提供，待客户端初始化任务加入 |
| 真实服务 | 阶段 0 不要求 API Key，使用占位或 mock 输入 |

移动端 workspace 必须继续使用根目录唯一的 `pnpm-lock.yaml`，不得在 `apps/mobile` 下单独生成 npm 或 yarn 锁文件。

## 3. 页面映射

| 页面 | 入口/目标 | 阶段 0 需要确认的输入 | 主要状态 |
|---|---|---|---|
| 首页 | 开始新计划、继续最近行程、浏览城市灵感 | 城市、日期、最近行程摘要 | 首次使用、已有行程、加载、空数据、网络错误 |
| 创建计划 | 收集城市、日期、住宿、同行人、兴趣、节奏、交通和饮食限制 | `Trip` 初始输入、`UserPreference` | 默认值、校验错误、提交中、提交失败 |
| 生成状态 | 展示行程生成进度和阶段性提示 | 计划 ID、生成状态、失败原因 | 生成中、生成成功、超时、可重试、服务失败 |
| 行程 | 按日期查看天气、时间线、地点、美食和交通 | `Trip`、`ItineraryItem`、`WeatherSnapshot` | 正常、加载、无行程、天气缺失、接口错误 |
| 地图 | 在行程页内切换到地图视图，显示当天站点和路线 | 地点坐标、路线结果、当前日期和选中站点 | 定位授权、地图加载、路线缺失、无网络、服务错误 |
| 地点详情 | 查看推荐理由、适合时段、营业信息、来源和更新时间 | `Place`、`OpeningInfo`、`ContentEvidence` | 正常、字段缺失、来源不可用、收藏失败 |
| 调整行程 | 替换地点、雨天备选、调整顺序、锁定安排 | 候选地点、约束、锁定项、重排结果 | 可编辑、重排中、无候选、约束冲突、保存失败 |
| 发现 | 浏览城市体验、主题路线、白天/夜间活动和美食 | 城市、主题、推荐卡片 | 加载、空数据、筛选无结果、网络错误 |
| 我的 | 查看保存行程、收藏、偏好和账户设置 | 已保存行程、收藏、偏好 | 未登录、加载、空数据、权限失败、退出确认 |

地图不是独立底部 Tab，而是行程页的视图模式。时间线和地图必须使用同一份当天行程数据；切换日期时同步更新时间线、地图标记和路线，点击卡片与地图标记需要能够双向定位。

## 4. 原型字段标记

### 可作为真实业务输入的字段

- 出行城市、到达/离开日期和时间。
- 住宿起点或出发位置。
- 同行人数、兴趣、节奏、交通方式和饮食限制。
- 当前日期、行程项顺序、锁定状态和用户调整动作。

### 当前仅为演示数据的字段

- 原型中的地点名称、图片、评分、天气、路线底图和距离。
- 推荐匹配度、推荐文案、开放时间和攻略来源展示内容。
- 示例行程中的重庆地点、日期和交通耗时。

### 阶段 1 需要确认的字段

- 试点城市及其地点类别范围。
- 真实地图/路线服务返回的坐标、距离和耗时格式。
- 天气预报时间范围与缺失数据处理。
- 来源卡片的授权、链接、发布时间和更新时间。
- 用户位置权限、地图权限和无网络时的展示策略。

## 5. 后续 Expo 初始化输入

客户端初始化时需要与 D、E 对齐：

1. Expo SDK、React Native 和导航依赖的兼容版本。
2. API 客户端和共享 contracts 的引入方式。
3. 地图 SDK 选择、平台权限和开发/生产密钥注入方式。
4. 定位、网络状态、推送和本地缓存是否纳入 MVP。
5. Android 模拟器与真机的最低验证矩阵。

在这些输入冻结前，不应提交真实地图 SDK、API Key、数据库或完整业务页面。
