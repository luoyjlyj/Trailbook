# 路书 Trailbook

根据出行时间、住宿位置、兴趣、营业信息、天气和交通路线，生成可查看、可调整的城市旅行计划。

> 当前状态：只有产品文档、两个可点击 HTML 原型和核心目录占位。应用、数据库、规划器以及外部服务均未实现。本次整理只精简目标与资料，不代表已经完成工程初始化。

## 这次要做出的产品

先做一个城市的完整流程：

填写出行信息 → 生成一至数日行程 → 查看时间线与地图 → 锁定或替换地点 → 局部重排 → 保存并重新打开。

原型使用重庆演示数据，正式试点城市仍需确认。首批地点由人工整理并核验，之后通过简单的管理后台维护。大模型用于理解需求、提取文本线索和解释结果；路线与时间安排由程序完成。

移动端保留首页、行程、发现、我的四个入口。发现页只展示少量人工维护的内容，我的页先提供已保存行程和偏好。地图属于行程页内的视图。

管理后台先做地点与营业信息维护、来源审核、行程查看和简单推荐参数配置。数据分析大屏、完整角色权限系统和服务运维控制台延后。

## 核心技术及用途

| 部分 | 技术 | 作用 |
| --- | --- | --- |
| 主要语言 | TypeScript | 编写界面、接口和规划逻辑 |
| 手机 App | React Native + Expo、Expo Router | 手机界面、设备能力和页面跳转 |
| 运营后台 | React + Vite、CSS | 浏览器里的管理页面及构建 |
| 后端 API | Node.js + Hono + Zod | 运行后端、接收请求、检查数据 |
| 数据保存 | MySQL + Prisma | 保存数据、用 TypeScript 读写数据库 |
| 行程规划 | TypeScript 自研逻辑 | 候选筛选、评分、时间排程和局部重排 |
| 外部信息 | 一家地图服务、一家天气服务、一家大模型服务 | 提供路线、天气及语言处理能力 |
| 通信 | HTTPS + JSON | 客户端和后端交换数据；本地可用 HTTP |
| 开发基础 | Node.js 24 LTS + pnpm | 运行开发工具、安装依赖和执行命令 |

手机 App 和后台都通过 API 访问数据。后端通过 Prisma 连接 MySQL，并调用规划器和外部服务；客户端不直接连接数据库。

## 当前目录

以下应用和模块目录只有一个占位文件，尚不是可运行项目：

```text
apps/
  mobile/       手机 App
  admin/        运营后台
  api/          后端 API，负责组合数据库、规划器和外部服务
packages/
  contracts/    共享数据类型与 Zod 校验规则
  database/     Prisma 数据模型和数据库访问
  planner/      行程规划逻辑
  providers/    地图、天气、大模型的服务端调用
docs/
  product/      产品范围
  architecture/ 技术结构、开发顺序和环境说明
  prototypes/   原型及其与首版范围的对应说明
```

保留同仓库目录只是为了组织代码。未来使用 pnpm workspace 连接内部模块，不引入额外任务编排工具，也不预建每一层页面和服务目录。

## 从哪里开始

1. 阅读[最小产品计划](docs/product/product-plan.md)，确认首版功能。
2. 阅读[最小实现方案](docs/architecture/minimal-implementation-plan.md)，按依赖顺序逐步开发。
3. 按[开发环境说明](docs/architecture/development-environment-setup.md)准备当前步骤需要的工具。
4. 查看[原型范围说明](docs/prototypes/README.md)，再打开[移动端原型](docs/prototypes/mobile-prototype.html)或[后台原型](docs/prototypes/admin-prototype.html)。

HTML 原型可以直接用浏览器打开。地点、天气、地图和“保存成功”等反馈均为演示，不代表真实服务或持久化。

当前没有 `package.json`、workspace 配置、数据库模型或启动脚本，不能按应用项目运行 `pnpm install` 或 `pnpm dev`。实际安装和启动命令将在实现对应工程时补充。

## 暂时不建设的部分

- 五人角色分工、并行任务编号、周计划、PR 审核流程和环境互验报告。
- CI/CD、提交钩子、全套代码检查工具、自动化测试平台和质量门禁。
- 共享 UI 框架、公共工具配置包及预先拆出的多层空目录。
- Redis、消息队列、微服务、Kubernetes、向量数据库和模型训练。
- 多城市、支付预订、社交、多人共编、自动批量采集和自动天气推送。

Docker、专用接口调试工具和 UI 组件库按实际需要选择，不是开工前置条件。未来正常产生的依赖锁文件、数据库迁移仍可保留，它们帮助重现安装和保存数据结构变化，不需要单独建设工具体系。

## 仍然要做对的事

精简工程管理后，仍需核验营业时间、真实交通耗时、返程缓冲、锁定项目和时间线/地图一致性。外部服务失败时明确说明缺少哪些信息，不用模拟数据冒充真实结果。

地点保留来源和更新时间；模型不能编造营业、距离或天气。服务端密钥只放在后端环境中。个人本地演示可暂缓用户登录；对外提供后台和私人行程前，需要基本认证与访问控制。
